# korean-ai-tone-check

긴 한국어 글의 AI 말투를 재고, 고친 뒤 원문과 대조하게 하는 Claude Code 스킬입니다.

A Claude Code skill that measures AI-style habits in long Korean prose and checks each revision against the original.

## 무엇을 하나

Claude가 800자가 넘는 한국어 글을 쓰거나 고쳤을 때 이 스킬을 따릅니다. 보고서, 계획서, 블로그 글, README 설명문, 긴 메일, 논문이 대상입니다.

1. 점검표를 들고 글을 읽습니다. 같은 결론을 되풀이하는 문단, 누가 하는지 빠진 문장, 무엇을 가리키는지 모를 '이는'을 찾습니다.
2. `scripts/measure.py`로 잽니다. 쉼표, 문장 길이, 끝맺음, 문두 접속어, '결론적으로', '다양한', '~는 것이 중요하다' 같은 표현을 세고, 사람이 쓴 글의 기준을 넘은 항목을 그 자리와 함께 보여 줍니다.
3. 고친 뒤 원문과 대조합니다. 바뀐 문장을 원문과 나란히 보여 주고, 숫자나 영문 표기가 달라진 곳과 문단을 옮긴 곳을 따로 알려 줍니다.

목표는 AI 탐지기를 피하는 것이 아니라 읽기 편한 글입니다. 수치는 다시 볼 자리를 알려 줄 뿐이고, 고칠지는 읽어 보고 정합니다.

## 설치

Claude Code와 Python 3.8 이상이 필요합니다. 스크립트는 표준 라이브러리만 씁니다.

개인 스킬 폴더에 `ai-tone-check`라는 이름으로 받습니다.

```bash
git clone https://github.com/JJeonJong/korean-ai-tone-check.git ~/.claude/skills/ai-tone-check
```

윈도우 PowerShell에서는 이렇게 받습니다.

```powershell
git clone https://github.com/JJeonJong/korean-ai-tone-check.git "$HOME\.claude\skills\ai-tone-check"
```

한 프로젝트에서만 쓰려면 그 프로젝트의 `.claude/skills/ai-tone-check`에 받습니다. 새 판은 받은 폴더에서 `git pull`로 받습니다.

## 쓰는 법

긴 한국어 글을 다 쓰고 나면 Claude가 스킬 설명을 보고 스스로 부를 수 있습니다. 직접 부를 때는 파일 경로를 넘기고, 논문이나 초록이면 `academic`을 붙입니다.

```
/ai-tone-check '보고서.md'
/ai-tone-check '논문.md' academic
```

SKILL.md의 `allowed-tools`는 이 스킬의 `measure.py`를 실행하는 명령만 허용합니다. 그 밖의 명령은 평소처럼 승인을 묻습니다.

스크립트만 따로 써도 됩니다. `python`이 없으면 `python3`으로 씁니다.

```bash
python scripts/measure.py '글.md'                     # 재기
python scripts/measure.py '글.md' --mark              # 재고, 지금 내용을 기준본으로 저장
python scripts/measure.py '글.md' --compare           # 고친 뒤 기준본과 대조
python scripts/measure.py --diff '전.md' '후.md'      # 두 파일 대조
python scripts/measure.py '논문.md' --genre academic  # 논문·초록 기준으로 재기
python scripts/measure.py '글.md' --forget            # 저장해 둔 기준본 지우기
```

기준본은 시스템 임시 폴더 안의 사용자 전용 폴더에 저장되고, 14일이 지나면 지워집니다.

## 출력 예

AI 글에 흔한 표현을 넣어 만든 예시 글(819자)을 잰 결과의 앞부분입니다.

```
ai-tone-check v2.2.1 측정 결과 (일반 글 기준. 다시 볼 곳을 알려 주는 수치이며 판정이 아님)
분량 819자(공백 포함), 한국어 문장 19개, 영어 문장 0개

확인 필요 8개 (같은 습관을 두 번 잰 항목을 묶으면 6가지: '~적', '다양한', 당부 표현, 문두 지시어, 문두 표지, 쉼표)
- 쉼표가 든 문장: 53% (10/19문장) (기준 50% 이하)
    1행: 특히 의료, 교육, 금융 등 다양한 산업에서 혁신적인 변화를 이끌고 있으…
    1행: 또한, 많은 기업이 업무 효율을 높이기 위해 인공지능을 적극적으로 도입하…
    1행: 이를 통해 반복적인 작업이 자동화되고, 사람은 더 창의적인 일에 집중할 …
    외 7건
- 연결어미·접속어 뒤 쉼표: 10회 (1,000자당 12.21) (기준 1,000자당 6.5 이하이거나 2회 이하)
    1행: … 혁신적인 변화를 이끌고 있으며, 그 영향력은 날로 커지고…
    1행: …력은 날로 커지고 있다. 또한, 많은 기업이 업무 효율을…
    1행: …를 통해 반복적인 작업이 자동화되고, 사람은 더 창의적인 일에…
    외 7건
```

이어서 문두 접속어, '결론적으로', '이는·이를 통해', '다양한', 당부 표현, '~적' 항목이 나오고, 참고와 통과 항목이 뒤따릅니다.

문단 하나를 앞으로 옮기면서 숫자 하나와 조건 하나를 바꾼 글을 원문과 대조한 결과입니다.

```
변경률(어절 단위): 32% (30% 초과)
자리를 옮긴 곳 1곳이 변경률에 들어 있습니다. 이를 빼면 5%(30% 이하)입니다.
바뀐 숫자: 사라짐 [2.5] / 새로 생김 [3]
바뀐 영문 표기: 없음
바뀐 곳 2곳: 숫자·영문 표기가 바뀐 곳 1, 숫자·영문 표기가 든 문장 0, 그 밖 1
원문과 나란히 읽으세요. 수치의 대상과 단위, 정의, 조건, 주체, 부정이 달라졌으면 되돌립니다.
  [표기 바뀜] "고객 문의는 평균 2.5일 안에 처리했다."
      → "고객 문의는 평균 3일 안에 처리했다." (자리도 옮김)
  [그 밖] "환불 요청은 담당자 승인이 있어야 처리된다."
      → "환불 요청은 바로 처리된다." (자리도 옮김)
문단 수: 4 → 4
자동으로 대조한 것은 숫자·영문 표기·문단 수뿐입니다. 뜻이 그대로인지는 바뀐 곳을 읽어 확인하세요.
```

## 기준값

일반 글 기준은 2022년 11월 이전에 사람이 쓴 한국어 기술 글의 절반으로 잡았습니다. 아래는 평가용으로 떼어 둔 글에서 "확인 필요"가 한 가지 이상 뜬 비율입니다. 사람이 쓴 기술 글은 기준을 잡을 때 쓰지 않은 나머지 절반입니다.

| 글 | 편수 | 비율 |
|---|---|---|
| 사람이 쓴 기술 글 | 231 | 18% |
| 경제 기사 | 195 | 11% |
| 학생 논증문 | 90 | 31% |
| 위키백과 | 60 | 55% |
| 2024년 모델이 쓴 논증문 | 295 | 98% |

문장 길이와 끝맺음은 한국어 문장이 20개 이상인 글에서만 잽니다. 이 규칙은 위 글들의 결과를 본 뒤에 정했습니다.

논문 기준(`--genre academic`)은 KatFish 데이터(Park 외, ACL 2025)의 연구자 논문·초록과 LLM 초록으로 잡았습니다. 항목별 기준과 근거는 SKILL.md에 있습니다.

## 한계

- 정규식으로 셉니다. 사람 이름 뒤의 쉼표나 인용 속 표현처럼 틀리게 잡는 자리가 있습니다.
- 기준을 기술 글에 맞췄습니다. 이름과 항목을 나열하는 설명문은 사람이 쓴 글도 자주 걸립니다(위키백과 55%).
- 지금 모델이 쓴 초안에서는 표시가 적게 뜹니다. 표시가 없다고 좋은 글이라는 뜻은 아니어서, 스킬은 측정보다 읽기를 먼저 하게 합니다.
- `--compare`가 자동으로 대조하는 것은 숫자, 영문 표기, 문단 수입니다. 뜻이 그대로인지는 바뀐 문장을 읽어야 압니다.
- 수치는 사람이 쓴 글과 AI 글의 차이를 잰 것입니다. 그 차이를 고치면 글이 좋아진다는 근거는 아닙니다.
- 리눅스의 Python 3.8, 3.11, 3.12, 3.13에서 시험했습니다. 윈도우와 macOS에서는 이 판을 아직 돌려 보지 않았습니다.
